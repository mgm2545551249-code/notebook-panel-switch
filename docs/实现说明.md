# 实现说明

界面采用 C#、WPF 和系统托盘；发行版包含 .NET 8 运行环境。管理员代理只负责监听系统按钮事件及临时接管电源按钮策略。

## 显示控制

`DisplayNative.Query` 读取当前或全部显示路径，通过输出技术识别内屏，并保存目标设备路径。恢复记录保存完整路径数组、模式数组和窗口位置，序列化保留原生结构中的联合体字节。

`IPanelBackend` 定义能力对应的准备、关闭、恢复和状态读取。已实测的是显示布局后端；独立电源后端只有在设备及驱动指纹对应的现场验证记录存在时才启用。

`Controller` 管理开启、正在关闭、关闭、正在恢复和故障五种状态。切换期间忽略重复请求，防止并发改动布局。退出、超时、故障和设备变化均进入恢复路径。

本机使用已签名的第三方用户模式间接显示驱动。没有外接屏时，虚拟显示器维持桌面目标，真实内屏路径被停用。软件不屏蔽普通输入，不使用黑色遮罩，也不反复发送关屏指令。

## 独立恢复

关闭之前先原子写入恢复记录，启动独立恢复进程，并等待其写入就绪标记。未就绪时取消关屏。

恢复进程检查原进程标识、启动时间、心跳和测试截止时间。主进程消失、心跳停止或测试超时触发恢复。主进程和恢复进程使用跨进程互斥量，避免同时应用恢复布局。

旧布局失效时尝试系统内屏布局；窗口恢复前核对窗口所属进程及其启动时间，避免把复用的窗口句柄移动到旧位置。

## 实体电源键

使用系统 `Microsoft-Windows-Kernel-Acpi` 提供程序，标识为 `c514638f-7723-485b-bcfc-96565d735d4a`。本机事件清单确认：事件24、版本0是按钮通知，包含设备实例、能力和事件掩码；事件25是请求完成。

代理接受事件24或25、版本0，要求 `EventMask & 1` 非零。设备名称既可能是即插即用标识，也可能是固件命名空间路径；本机实测为 `\_SB.PWRB`。同一次按压产生的通知和完成记录通过去抖合并，盖子和睡眠按钮不触发屏幕开关。

事件负载按本机清单解析：开头两字节为设备名字符数，随后是对应长度的宽字符名称；事件24还包含四字节能力字段，之后是四字节事件掩码。事件25在名称后直接包含事件掩码。解析前检查事件版本和字段边界。

普通用户界面创建随机命名管道，限制当前用户连接，并核对客户端进程标识。管理员代理只向界面发送固定按钮通知，并接受心跳或退出指令，不提供任意命令执行能力。

代理接管前保存电源按钮原配置，接电、电池均暂设为“不采取操作”；退出、管道断开、主进程消失或十秒没有心跳时还原配置。不存在需要安装自编译内核过滤驱动的步骤。

## 开发命令

```powershell
./发行版/PanelSwitch.exe --diagnose ./诊断.json
./发行版/PanelSwitch.exe --self-test ./自动测试.json
./发行版/PanelSwitch.exe --recover
```

以下命令会真实切换显示路径，只用于开发验收：

```powershell
./发行版/PanelSwitch.exe --integration-test ./实机测试.json 2
./发行版/PanelSwitch.exe --timeout-test ./超时恢复.json
./发行版/PanelSwitch.exe --crash-test ./异常退出触发.json
```

异常退出测试故意返回23，由独立进程恢复显示。所有真实显示测试应在退出常驻程序后单独运行，防止两个控制器竞争同一份恢复记录。
